# ونسة — تطبيق مراسلة برقم الجوال (Firebase)

تسجيل دخول برقم الجوال ورمز تحقق حقيقي (Firebase Authentication)، ومحادثات فورية بين مستخدمين حقيقيين (Cloud Firestore)، ويُنشر على Firebase Hosting. لا يحتاج الموقع إلى خادم أو أداة بناء: ملفات HTML وCSS وJavaScript فقط.

## ما الذي يعمل

- التسجيل برقم الجوال ورمز من 6 أرقام. الحساب الجديد يختار اسمه ولون صورته.
- إضافة صديق برقمه (يجب أن يكون مسجّلاً في ونسة)، ومحادثات فورية بين الجهازين.
- عدّاد غير المقروء، وعلامة قراءة مزدوجة عند فتح الطرف الآخر للمحادثة.
- «متصل الآن» و«آخر ظهور»، والعمل مع انقطاع الاتصال (تُرسَل الرسائل عند عودته).
- عربي من اليمين لليسار، ووضع فاتح وداكن حسب الجهاز.

## الإعداد (مرة واحدة)

### 1) أنشئ مشروع Firebase
من [console.firebase.google.com](https://console.firebase.google.com) اضغط **Add project**.

### 2) فعّل الدخول برقم الجوال
**Build ← Authentication ← Get started ← Sign-in method ← Phone ← Enable**.

ثم افتح **Authentication ← Settings ← SMS region policy** وتأكد أن دولتك (مثل السودان) مسموحة. إن كانت الدولة محظورة ستظهر رسالة «الدخول برقم الجوال غير مفعّل».

### 3) أنشئ قاعدة Firestore
**Build ← Firestore Database ← Create database**، اختر أقرب موقع لمستخدميك، وابدأ في **Production mode** (القواعد الجاهزة في هذا المشروع تُنشر في الخطوة 6).

### 4) انسخ إعدادات تطبيق الويب
**Project settings ← General ← Your apps ← Web (`</>`)** سجّل التطبيق، ثم انسخ كائن `firebaseConfig` والصقه في الملف:

```
public/firebase-config.js
```

### 5) ثبّت أداة Firebase وسجّل الدخول
```bash
npm install -g firebase-tools
firebase login
```
ثم افتح `.firebaserc` وضع معرّف مشروعك مكان `YOUR_PROJECT_ID` (أو نفّذ `firebase use --add`).

### 6) انشر
```bash
firebase deploy
```
يرفع الموقع وقواعد الأمان معاً، ويعطيك رابطاً مثل `https://مشروعك.web.app`.

## التجربة قبل إرسال رسائل حقيقية

من **Authentication ← Sign-in method ← Phone ← Phone numbers for testing** أضف رقمين وهميين مع رمز ثابت لكل واحد (مثل `+249 900000001` والرمز `123456`). تسجّل بهما من متصفحين مختلفين وتتبادل الرسائل دون أي رسالة نصية فعلية ودون رسوم.

للتشغيل المحلي: `firebase emulators:start --only hosting` أو `npx serve public`. النطاق `localhost` مصرّح به تلقائياً في Authentication.

## التكلفة

- الدخول برقم الجوال يرسل رسائل نصية حقيقية، ولها حد مجاني ثم رسوم، وقد يتطلب مشروعك خطة Blaze (الدفع حسب الاستخدام). راجع صفحة أسعار Firebase Authentication قبل الإطلاق.
- Firestore يحسب القراءات والكتابات. التطبيق يكتب «آخر ظهور» مرة كل دقيقة لكل مستخدم يفتح الصفحة، وهذا الجزء الأكبر من الكتابات غير الرسائل.

## بنية البيانات

| المسار | المحتوى |
|---|---|
| `users/{uid}` | الاسم، الرقم، اللون، الحالة، آخر ظهور |
| `phones/{الرقم}` | `{ uid }` فهرس للبحث عن صديق بالرقم |
| `chats/{uidA_uidB}` | الأعضاء، آخر رسالة، عدّادات غير المقروء، أوقات القراءة |
| `chats/{id}/messages/{id}` | `{ from, text, createdAt }` |

معرّف المحادثة هو معرّفا المستخدمين مرتّبين أبجدياً، فلا تتكرر المحادثة بين شخصين.

## الأمان (firestore.rules)

- كل شيء يتطلب تسجيل دخول.
- لا أحد يستطيع سرد المستخدمين أو الأرقام، فقط جلب ملف إذا عرف معرّفه أو رقمه.
- فهرس الأرقام لا يُكتب إلا لمن أثبت ملكية الرقم عبر رمز الرسالة.
- المحادثات والرسائل مقروءة لعضويها فقط، والرسائل لا تُعدَّل ولا تُحذف، ويُختم وقتها من الخادم.

جرّب القواعد قبل الإطلاق من **Firestore ← Rules ← Rules Playground**، أو بمحاكي Firebase.

## حدود هذه النسخة

- الرسائل غير مشفّرة من طرف إلى طرف. هي محمية بالقواعد ومخزّنة على Firestore.
- التحقق من وجود رقم يتم بالتجربة المباشرة، فيمكن لمستخدم مسجّل أن يختبر وجود أرقام. يُنصح بتفعيل **App Check** (مع reCAPTCHA Enterprise) قبل الإطلاق العام.
- القواعد تسمح للطرفين بتعديل عدّاد غير المقروء عند الآخر لأن الإرسال يزيده. لتشديدها انقل منطق الإرسال إلى Cloud Functions.
- لا توجد إشعارات دفع عند إغلاق الصفحة. تُضاف عبر Firebase Cloud Messaging مع Cloud Function.
- الصور والملفات والمجموعات غير مدعومة بعد.

```
  index.html           الواجهة
  styles.css           التصميم

  js/firebase.js       تهيئة Firebase (إصدار SDK 10.14.1)
  js/util.js           الدول والأرقام والتواريخ
  js/app.js            الدخول والمحادثات

.firebaserc            معرّف المشروع
```
